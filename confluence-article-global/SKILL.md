# confluence-article-global — статья, готовая к вставке в Confluence

Цель — получить два согласованных артефакта: Markdown-источник, который удобно
править, и `.txt` с Wiki Markup, который вставляется в Confluence без потерь.
Разметка проверяется до вставки, а не после.

Скилл ничего не публикует: он готовит файлы и отчёт проверки.

## Активация

Включение: загрузка скилла либо фраза — «сделай статью для Confluence»,
«wiki-разметка», «подготовь страницу Confluence», «статья под Confluence», «/confluence».
Выключение: «хватит», «обычный режим».

## Контракт

| Артефакт | Формат | Назначение |
|---|---|---|
| `<name>.md` | Markdown, UTF-8 без BOM, LF | источник, правка, ревью |
| `<name>.txt` | Confluence Wiki Markup, UTF-8 без BOM, CRLF | вставка в Confluence |
| отчёт `check-wiki.pl` | stdout, код возврата | PASS или список FAIL/WARN |

`.md` — источник истины. `.txt` всегда перегенерируется скриптом, руками не правится.

## Заголовки

Заголовок страницы в Confluence — отдельный title. Поэтому H1 в документе не используется
как заголовок раздела.

| Режим | Что в `.md` | Команда | Результат в `.txt` |
|---|---|---|---|
| Статья с title | `#` — первый раздел | `--drop-first-h1` не нужен | `#` → `h2.`, `##` → `h3.` |
| Статья, где первый H1 — title | `# Заголовок статьи` + `##` разделы | `--drop-first-h1` | первый `#` пропускается, `##` → `h2.` |
| Фрагмент в существующую страницу | `#` — раздел | `--base 3` | `#` → `h3.` |

Правило: в `.md` не должно быть двух H1. Один H1 допустим только как title
и только в режиме `--drop-first-h1`.

## Правила разметки

### Ссылки

| В `.md` | В `.txt` | Условие |
|---|---|---|
| `[текст](http://host/pages/viewpage.action?pageId=123)` | `[текст|page:123]` | ссылка на страницу Confluence |
| `[текст](http://host/page)` | `[текст|http://host/page]` | внешняя ссылка |
| `[текст](file.xlsx)` | `[текст|^file.xlsx]` | файл должен быть прикреплён к странице |
| `[текст](#anchor)` | `[текст|#anchor]` | якорь объявляется `{anchor:anchor}` перед заголовком |

Запрещено: `<a href="...">` (не конвертируется), относительные пути без вложения,
ссылки с `|` внутри ячеек таблиц (символ ломает таблицу).

### Таблицы

- В `.md` — обычные pipe-таблицы; первая строка — заголовок.
- В `.txt` заголовок получает `||`, данные — `|`; разделитель `|---|` удаляется.
- Число колонок в заголовке и строках обязано совпадать: валидатор проверяет.
- Ссылки, макросы и блоки кода внутри ячеек — не размещать. Ссылку с `|` выносить под таблицу.

### Код и макросы

| В `.md` | В `.txt` |
|---|---|
| ````` ```lang ```` | `{code:language=lang}` ... `{code}` |
| `<details><summary>Заголовок</summary>` | `{expand:Заголовок}` ... `{expand}` |
| `[!NOTE]`-блок | `{note}` ... `{note}` |
| `[!WARNING]`-блок | `{warning}` ... `{warning}` |

Вне `{code}` не должно оставаться `{` и `}`: Confluence примет их за макрос и покажет
«Unknown macro». Внутри `{{inline}}` символы `*`, `[`, `]`, `#` экранируются как
`&#42;`, `&#91;`, `&#93;`, `&#35;`.

### Изображения

`![alt](http://host/img.png)` → `!alt|http://host/img.png!`.
`![alt](img.png)` → `!^img.png!`; файл должен быть прикреплён.

### Кодировка

- `.txt` — UTF-8 без BOM, окончания строк CRLF: иначе shell- и Wiki-парсеры видят мусор.
- `.md` — UTF-8 без BOM, LF.
- Проверка BOM и окончаний входит в валидатор.

## Процесс

1. Собрать или обновить `<name>.md`. Один H1 максимум, таблицы без ссылок в ячейках.
2. Выбрать режим: статья (`--drop-first-h1`, если H1 — title) или фрагмент (`--base 3`).
3. Сгенерировать Wiki Markup:
   ```
   perl scripts/md2wiki.pl --in article.md --out article.txt --drop-first-h1
   ```
4. Проверить:
   ```
   perl scripts/check-wiki.pl article.txt
   ```
5. Исправить `.md` и повторить шаги 3–4 до `PASS`. Отдать оба файла и отчёт.

Правки в `.txt` руками запрещены: следующая генерация их затрёт.

## Валидация

`check-wiki.pl` возвращает код 1 при FAIL.

| Проверка | Уровень |
|---|---|
| BOM в начале файла | FAIL |
| Нет CRLF или смешаны LF и CRLF | FAIL |
| `h1.` в тексте | FAIL |
| Несбалансированные `{{` / `}}` | FAIL |
| Нечётное число `{code}`, `{expand}`, `{note}`, `{info}`, `{warning}` | FAIL |
| `{` или `}` вне `{{...}}` и макросов | FAIL |
| Число колонок в таблице не совпадает | FAIL (ссылка с `|` в таблице — WARN) |
| Нечётное число `*` вне кода | WARN |
| Ссылка `^файл` без приложенного файла | проверить вручную |

## Краевые случаи и запреты

- **Одиночная `*`** открывает жирный шрифт и съедает текст до следующей `*`. В тексте писать
  `PROPTYPE_` без звёздочки или экранировать `~*`.
- **`|` в ссылке внутри таблицы** — всегда выносить ссылку из таблицы.
- **Вложения** не создаются вставкой разметки: файл прикрепляется к странице отдельно,
  ссылка `^файл` работает только после загрузки.
- **HTML** (`<a>`, `<br>`, `<table>`) не конвертируется и в Wiki остаётся мусором.
- **Storage-формат** (XHTML) — другой инструмент; скилл его не делает.
- **Markdown-вставка в редактор Confluence** зависит от версии и теряет часть разметки;
  Wiki Markup `.txt` — предсказуемый путь.

## Портируемость

- Зависимости: `perl` (стандартный, без модулей CPAN) и POSIX shell.
- Пути не зашиты: работают `--in`/`--out`, абсолютные и относительные.
- Ничего не публикует, не читает сеть, не требует токенов.
- Перенос — копирование каталога `confluence-article-global/` в
  `~/.pi/agent/skills/` или `.pi/skills/`.

## Обслуживание

- `scripts/md2wiki.pl` — конвертер; правила соответствия в `references/markup-cheatsheet.md`.
- `scripts/check-wiki.pl` — валидатор; новый FAIL добавлять с тестом на образце.
- Проверка после правок:
  ```
  perl scripts/md2wiki.pl --in references/sample.md --out /tmp/sample.txt --drop-first-h1
  perl scripts/check-wiki.pl /tmp/sample.txt
  ```
  Ожидаемый итог — `PASS` (допустимы WARN).
